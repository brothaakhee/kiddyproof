# kiddyproof — Verified Architecture
> Produced by an adversarial multi-agent design loop (propose → challenge → web-verify → synthesize). 19 agents, ~333 web/tool lookups.

**Feasibility verdict:** `feasible-with-caveats`

## Summary

kiddyproof is buildable as a real, notarized, direct-download macOS app (Apple Silicon, Sonoma/Sequoia), but ONLY if the product promise is scoped honestly to "best-effort: blocks all typing, clicking, scrolling, and standard window/Mission-Control keyboard shortcuts" rather than "ALL input blocked, zero effect." Every load-bearing mechanism is verified to work: a suppressing CGEventTap at kCGSessionEventTap + headInsert (Accessibility-granted) reliably swallows ordinary keyboard/mouse/scroll and most chord shortcuts (Cmd-Space, Cmd-Tab, screenshots, Cmd-Q); a transparent borderless overlay at a high window level over an accessory-policy app covers menu bar/Dock/all normal Spaces; a mouse-corner-hold exit gesture survives Secure Event Input; and self-contained Metal/CoreAnimation effects (ripples, big letters, particle bursts) need no special permission. The transparent-overlay approach is the right call over screen-capture for the BASE product (state is preserved by simply dropping events; no capture permission, no latency, no energy cost) — confirmed by the debate. HOWEVER there is a hard, verified set of irreducible failures parents must accept, none of which have a clean userspace fix: (1) Secure Event Input (any focused password field / Terminal-with-secure-entry / 1Password / sudo / FileVault prompt) makes keystrokes invisible AND unblockable — they flow straight into the secure field; kid mode must detect this, hard-refuse to arm, and continuously poll-and-bail. (2) A small set of OS-reserved escapes — the hardware power/Touch-ID button, Force Quit (Cmd-Opt-Esc), accessibility shortcuts (Cmd-F5 VoiceOver, triple-press Touch ID), idle/lid-close lock, and 3/4-finger Mission Control trackpad swipes — are dispatched below/beside a non-root session tap and CANNOT be guaranteed-blocked. (3) Covering ANOTHER app's native-fullscreen Space (Safari video, Keynote, a game) and Stage Manager groupings has no clean public API and is genuinely unsolved — the overlay renders behind foreign fullscreen content. The critical safety risks (parent lockout, silent input leak) are all mitigable but mandatory: a non-nil tap is NOT a healthy tap (silent-disable race), so the app must verify live event flow before declaring "armed"; TCC revocation mid-session can wedge input until reboot, so an EXTERNAL watchdog process that SIGKILLs the main app (process death tears the tap down and restores input) is the load-bearing failsafe, never in-callback self-detection. The "black hole that warps the real desktop" is a separate, fragile, opt-in pro tier requiring ScreenCaptureKit + Screen Recording permission — the base product must be delightful without it. The marquee headline is the fragile part; the safety foundation is solid if built defensively.

## Recommended stack

Language/UI: Swift + AppKit (NSWindow/NSApplication, NSPanel for the overlay). SwiftUI only for the parent-facing settings/onboarding panel; the kid-mode overlay and effects are pure AppKit + Metal for frame-pacing control. Input: Core Graphics CGEventTap (Quartz Event Services) at kCGSessionEventTap + kCGHeadInsertEventTap, kCGEventTapOptionDefault, on a dedicated high-priority CFRunLoop thread (never main). Cursor: CGAssociateMouseAndMouseCursorPosition(false) + CGDisplayHideCursor (app must be frontmost). Effects Tier A (ships first): MTKView/CAMetalLayer (opaque=false) for GPU particles/SDF glyphs + Core Animation for cheap ripples — NO special permission. Effects Tier B (opt-in pro, later): ScreenCaptureKit (SCStream, SCContentFilter application-level self-exclusion, capture-once-and-freeze) → CVMetalTextureCache → UV-displacement fragment shader; requires Screen Recording TCC. Kiosk hardening: NSApplication.presentationOptions (.disableForceQuit, .disableProcessSwitching, .disableSessionTermination, .disableHideApplication, .autoHideMenuBar, .autoHideDock, .disableAppleMenu). Sleep/lock: IOPMAssertion (kIOPMAssertionTypePreventUserIdleDisplaySleep) + NSWorkspace lock/sleep notifications. Safety: a separate bundled watchdog helper process (same Team ID, no taps, monitors heartbeat via dispatch source on PID + XPC ping/pong, owns the max-duration deadline, SIGKILLs main on hang/timeout). Distribution: Developer ID Application signing + Hardened Runtime + notarytool notarization + stapled DMG. NOT sandboxed, NOT Mac App Store (CGEventTapCreate returns NULL under App Sandbox). Activation policy: LSUIElement / .accessory — NEVER LSBackgroundOnly (breaks tapCreate on Sequoia). Permissions: Accessibility (mandatory, for the suppressing tap) + Screen Recording (only for Tier B warp).

## Components

### InputSuppressor (CGEventTap engine)

Owns a single suppressing CGEventTap at kCGSessionEventTap + headInsert (kCGEventTapOptionDefault) running on a DEDICATED high-priority CFRunLoop thread — never the main/UI thread. While idle the tap is pass-through (returns the event); on kid-mode arm it flips to swallow-mode (returns NULL for everything EXCEPT the recognized exit gesture and an intentionally-whitelisted Force-Quit chord). The callback does ZERO work beyond: classify event, copy a tiny event summary into a lock-free ring buffer for the renderer, update the exit-gesture state machine, and return. Handles kCGEventTapDisabledByTimeout AND kCGEventTapDisabledByUserInput by immediately re-enabling. Masks keyDown/keyUp/flagsChanged, full mouse set, scrollWheel, otherMouse, tablet, and NSSystemDefined (media keys, extracted via the SPMediaKeyTap data1 bit-pattern).

**Key APIs:** `CGEventTapCreate(tap:.cgSessionEventTap, place:.headInsertEventTap, options:.defaultTap, ...)`, `CGEvent.tapEnable(tap:enable:) / CGEventTapIsEnabled`, `CGEventType.tapDisabledByTimeout / .tapDisabledByUserInput`, `CFMachPortCreateRunLoopSource / CFRunLoopAddSource (dedicated thread)`, `CGEventMaskBit incl. NX_SYSDEFINED (bit 14)`

### CursorController

Freezes the physical pointer (returning NULL does NOT stop cursor motion — verified). On arm: CGAssociateMouseAndMouseCursorPosition(false) to decouple physical movement from the cursor, then CGDisplayHideCursor; draws the app's own black-hole cursor from tap-observed deltas. On exit: balanced CGDisplayShowCursor + CGAssociateMouseAndMouseCursorPosition(true) (call associate(true) right after hide to avoid the Barrier not-hiding bug). Requires the app to be frontmost (cursor APIs are foreground-only), so kiddyproof activates itself on arm. Re-asserts on display reconfiguration.

**Key APIs:** `CGAssociateMouseAndMouseCursorPosition(_:)`, `CGDisplayHideCursor(_:) / CGDisplayShowCursor(_:)`, `CGWarpMouseCursorPosition(_:) (optional pin)`, `NSApplication.activate`

### OverlayWindowManager

Defense-in-depth visual layer AND a real second input barrier (NOT cosmetic). One borderless non-activating NSPanel per NSScreen at a high window level (.screenSaver / CGShieldingWindowLevel-class), isOpaque=false, backgroundColor=.clear, collectionBehavior=[.canJoinAllSpaces, .stationary, .ignoresCycle] (NOT .fullScreenAuxiliary — it renders BEHIND foreign fullscreen). App runs .accessory policy so overlays can float over apps. Even if the tap dies, the key overlay absorbs clicks/keys to itself rather than the apps below. Reconciles displays INCREMENTALLY via CGDisplayRegisterReconfigurationCallback (keyed by CGDirectDisplayID) — never tear-down/rebuild-all (avoids coverage gap). Sets NSApp.presentationOptions kiosk flags as OS-level hardening independent of the tap.

**Key APIs:** `NSPanel (.nonactivatingPanel, borderless)`, `NSWindow.level / collectionBehavior`, `NSApplication.presentationOptions`, `CGDisplayRegisterReconfigurationCallback`, `NSApplication.didChangeScreenParametersNotification`

### ExitGestureController

Detects the deliberate parent-exit gesture WITHOUT depending on the keyboard tap (which Secure Event Input can kill). Primary: a mouse/trackpad press-and-hold in a fixed screen corner for >= 3s (mouse events survive SEI). Secondary: a 3-modifier keyboard chord (Ctrl+Opt+Cmd) held 3s, recognized inside the tap and explicitly passed/acted-on (not blanket-NULLed). Any non-gesture event resets the timer. Drives a visible progress ring so a parent gets feedback. Toddler random-mashing is statistically unable to reproduce a timed corner-hold.

**Key APIs:** `lock-free ring buffer drained on a timer thread`, `NSEvent.mouseLocation / tap-observed deltas`, `CGEvent.flags masking (maskControl|maskAlternate|maskCommand)`

### TapHealthMonitor

Solves the silent-disable race ('a non-nil tap is not a healthy tap'). Before declaring kid mode ARMED, verifies at least one REAL event flowed through the callback within a short window (live heartbeat), not just that tapCreate returned non-NULL. Continuously confirms the tap is enabled AND receiving events; on dead-but-enabled, recreates the tap from scratch; if it cannot be restored, FAILS LOUD (visible parent alert) and tears kid mode down rather than leaving an overlay over leaking input. Re-creates the tap on NSWorkspace sleep/wake and session-active notifications.

**Key APIs:** `CGEventTapIsEnabled`, `CGPreflightListenEventAccess / AXIsProcessTrusted (revalidate)`, `NSWorkspace willSleep/didWake/sessionDidBecomeActive`

### SecureInputGuard

Handles the irreducible Secure Event Input gap. On arm: IsSecureEventInputEnabled()==true → HARD-REFUSE to enter kid mode and show the parent a generic remediation message (do NOT trust kCGSSessionSecureInputPID to name the culprit — verified unreliable for background owners). During kid mode: poll every ~100-250ms; on transition to enabled, immediately throw a loud full-screen 'BLOCKING DEFEATED — exit now' banner and/or auto-exit. Never calls DisableSecureEventInput on other processes (forbidden/unsafe). Also moves focus to its own non-text overlay on arm so kiddyproof itself never holds secure input.

**Key APIs:** `IsSecureEventInputEnabled() (Carbon)`, `kCGSSessionSecureInputPID (best-effort hint only)`

### WatchdogHelper (separate process)

The load-bearing parent-lockout failsafe. A bundled sibling helper (same Team ID, notarized in-bundle, NO suppressing tap so it can never be wedged by SEI/timeout/revocation) launched as a child of the main app — no Login Items approval, no extra Gatekeeper prompt. Monitors the main app via a dispatch source on its PID (EVFILT_PROC/NOTE_EXIT) + an XPC ping/pong with a deadline (NOT racy file-mtime). If the heartbeat stops or the max-duration deadline passes, it SIGKILLs the main app — process death drops the tap and restores input. Owns the authoritative auto-exit deadline (an in-process timer is starved during a livelock, so it cannot be trusted for this).

**Key APIs:** `DispatchSource.makeProcessSource (NOTE_EXIT)`, `XPC connection (interruption/invalidation handlers + ping/pong)`, `kill(2) (same-uid, no TCC needed)`

### EffectsRenderer (Tier A)

Renders self-contained kid-mode FX driven by the ring-buffer event stream on a CADisplayLink/CAMetalDisplayLink clock — NEVER in the tap callback. MTKView (CAMetalLayer opaque=false, premultiplied-alpha, clearColor (0,0,0,0)) for GPU particle bursts and SDF animated glyphs; Core Animation for cheap click ripples. Idle/paused when no input. One renderer per overlay window. Needs NO special permission. This is the shippable visual product.

**Key APIs:** `MTKView / CAMetalLayer (isOpaque=false)`, `MTLRenderPipeline premultiplied blend (.one / .oneMinusSourceAlpha)`, `CADisplayLink / CAMetalDisplayLink`, `ProcessInfo.thermalState (auto-downgrade)`

### WarpRenderer (Tier B, opt-in pro, later)

Optional real-desktop 'black hole' lens. Pre-flights Screen Recording TCC during onboarding (never prompts mid-session). Captures the frozen desktop ONCE (capture-once-and-freeze — the desktop is input-frozen so re-capture is unneeded and avoids thermal load + frame-starvation), excludes kiddyproof at the APPLICATION level (SCContentFilter excludingApplications — never the empty-window array that stalls the stream, never NSWindow.sharingType which no longer works on 15.4+), wraps the IOSurface as an MTLTexture, and runs a radial UV-displacement fragment shader clocked off the overlay display link. Auto-falls-back to Tier A on missing permission, black frames, feedback, or thermal pressure. One SCStream per display; teardown/rebuild on display reconfiguration.

**Key APIs:** `SCStream / SCContentFilter(display:excludingApplications:exceptingWindows:)`, `CVMetalTextureCacheCreateTextureFromImage`, `CGPreflightScreenCaptureAccess`, `ProcessInfo.thermalState`

### OnboardingAndPermissions

Parent-facing SwiftUI flow: requests Accessibility via AXIsProcessTrustedWithOptions(prompt:true), deep-links to System Settings, polls until granted, and instructs the required relaunch. Verifies the suppressing tap actually works (creates + confirms live event flow) before allowing kid mode. Documents the residual escapes honestly (power button, Force Quit, secure fields, foreign fullscreen). Optionally requests Screen Recording for Tier B.

**Key APIs:** `AXIsProcessTrustedWithOptions([kAXTrustedCheckOptionPrompt:true])`, `AXIsProcessTrusted`, `CGRequestScreenCaptureAccess (Tier B only)`

## Permissions required

- Accessibility (Privacy & Security > Accessibility) — MANDATORY for the suppressing kCGEventTapOptionDefault tap; Input Monitoring alone is NOT sufficient for suppression. Granted manually by the parent; typically requires an app relaunch to take effect.
- Screen Recording (Privacy & Security > Screen Recording) — ONLY for the optional Tier B desktop-warp effect (ScreenCaptureKit). The base product needs none.
- No root and no DriverKit entitlement for v1 (session tap, not HID). A root HID tap or DriverKit virtual-HID would be required to block the residual OS-reserved chords — explicitly out of scope.
- Watchdog helper needs NO TCC permission (SIGKILL of a same-uid process requires none) and, if bundled + same-Team-ID + child-launched, needs no Login Items approval.

## Killer edge cases (must disclose to parents)

- Secure Event Input: if a password field, Terminal-with-Secure-Keyboard-Entry, 1Password, sudo, or FileVault prompt is focused, a toddler's keystrokes go straight into it with full effect and cannot be blocked OR observed. kiddyproof must refuse to arm and bail if it turns on mid-session — there is NO userspace fix.
- Hardware power / Touch ID button: cannot be intercepted at all. A toddler pressing it can sleep/lock/show the power dialog. (Locking preserves document state, but drops out of kid mode.)
- Force Quit (Cmd-Opt-Esc) and accessibility shortcuts (Cmd-F5 VoiceOver, triple-press Touch ID, Opt-Cmd-8 Zoom): dispatched below/beside a non-root session tap; a mashing toddler can plausibly trigger these and they are not guaranteed-blocked.
- Another app in native fullscreen (Safari video, Keynote, a game) or Stage Manager: the overlay renders BEHIND foreign fullscreen content — the real app stays visible (input is still tap-blocked, but the visual cage and FX are absent). No clean public API solves this.
- 3/4-finger Mission Control / Spaces / Launchpad trackpad swipes: derived from raw multitouch by WindowServer/Dock, not from suppressible CGEvents — a flat-hand toddler swipe can switch Spaces or open Mission Control.
- Idle / lid-close auto-lock: fires on a timer or hardware regardless of the overlay; mitigated by an IOPMAssertion to prevent display sleep, but lid-close and an explicit Cmd-Ctrl-Q lock are not reliably blockable.
- TCC revocation mid-session can wedge input until the watchdog SIGKILLs the app (or, in rare wedge states, until a hardware reboot) — the watchdog makes the common case safe, but instantaneous restoration is not contractually guaranteed.
- The marquee 'black hole that warps the real desktop' is the fragile, permission-heavy, opt-in part — parents should expect the shippable experience to be self-contained particles/ripples/letters, with true desktop warp as a best-effort bonus that degrades gracefully.

## POC plan

**Goal:** Prove the three riskiest mechanisms end-to-end on a developer's Apple Silicon Mac (Sonoma/Sequoia): (1) a suppressing CGEventTap that truly blocks keyboard+mouse+scroll from underlying apps while still observing events for visuals AND freezes the physical cursor; (2) a transparent full-screen overlay that covers the menu bar/Dock/normal Spaces and renders click ripples + big keystroke letters with zero capture; (3) a robust two-channel exit (mouse corner-hold + modifier chord) that survives even when the keyboard tap is defeated, backed by an external watchdog that guarantees the parent can never be locked out. Explicitly demonstrate the failure modes (silent-disable race, secure-input bail, watchdog SIGKILL restore) rather than hiding them. Tier B warp is OUT of POC scope — prove the transparent-overlay foundation first.

**Steps:**

1. 0. Scaffold: create Package.swift with two executable targets (kiddyproof, Watchdog). Set .accessory activation policy. Build and run an empty agent app (no Dock icon).
2. 1. Permissions gate: implement Permissions.swift — prompt for Accessibility, deep-link to System Settings, poll AXIsProcessTrusted, instruct relaunch. MANUAL GRANT REQUIRED here (cannot be automated).
3. 2. Suppressor core: implement InputSuppressor.swift on a dedicated thread; start in pass-through, log every event type. Verify the callback fires for keys/mouse/scroll. Confirm tapCreate returns non-NULL only after Accessibility is granted.
4. 3. Health-gated arm: implement TapHealthMonitor — flip to swallow-mode only after confirming a real event flowed (defeat the silent-disable race). Add tapDisabled* re-enable.
5. 4. Prove suppression: in swallow-mode, open TextEdit + Safari underneath; type and click — confirm NOTHING reaches them. Run the interception matrix (Cmd-Space, Cmd-Tab, Cmd-Q, screenshot, Cmd-F5, 3/4-finger swipe, Cmd-Opt-Esc) and RECORD what leaks (expect accessibility shortcuts, power, Force Quit, foreign-fullscreen swipes to leak).
6. 5. Cursor freeze: implement CursorController; confirm the physical pointer no longer moves the system cursor and cannot trigger hot corners/Dock reveal; confirm balanced restore on exit + crash-safe restore via signal handler.
7. 6. Overlay: implement OverlayWindowManager — one clear NSPanel per screen at .screenSaver level covering menu bar/Dock on all normal Spaces; verify it stays on top across Space switches; note (expected) failure over a foreign fullscreen app.
8. 7. Effects: implement EffectsView reading the ring buffer — click ripples, big keystroke letters, cursor-following sprite at 60fps with zero capture permission.
9. 8. Exit gesture: implement ExitGestureController — corner-hold + modifier chord with progress ring; verify a toddler-style random mash does not trigger it and a deliberate hold does.
10. 9. Watchdog: implement Watchdog helper + heartbeat; kill -STOP the main app (simulate livelock) and confirm the watchdog SIGKILLs it and input is restored within ~1s. Also test the max-duration auto-exit.
11. 10. Secure-input + revocation drills: focus a Terminal with Secure Keyboard Entry → confirm SecureInputGuard hard-refuses/bails loudly; revoke Accessibility mid-session → confirm the watchdog restores input (document if a hardware reboot is ever needed). Record all residuals in POC_TEST_PLAN.md.
12. 11. Sign + notarize: Developer ID + Hardened Runtime + notarytool + staple a DMG; relaunch via Finder (NOT Xcode) to surface the Launch-Services silent-disable race; confirm the health gate catches it.
